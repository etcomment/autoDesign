Documentation du DSL autoDesign

autoDesign utilise un Domain Specific Language (DSL) pour representer les templates visuels sous forme de texte. Ce DSL est parse par le moteur du template system et converti en donnees structurees (objets TypeScript) que le rendu graphique utilise ensuite.

Le DSL est concu pour etre lisible et editable manuellement. Chaque template est defini par un en-tete (header) qui declare son type et optionnellement un titre, suivi de champs definissant le contenu.

Nouveautes : drag & drop de shapes et icônes, export SVG/PNG/JPG/PPTX avec contenu complet, copier-coller image vers d'autres applications, 53 icônes SVG intégrées.

Syntaxe generale #

En-tete (Header)

Chaque fichier DSL commence par un en-tete unique sur la premiere ligne :

@type variante "Titre du template"
  • @type — le type de base du template (ex: roadmap, process, strategy)
  • variante — un numero optionnel (ex: 4 pour @roadmap 4). Sans numero, c'est la variante 1.
  • "Titre" — un titre optionnel, entre guillemets simples ou doubles

Syntaxe des champs

  • Les champs sont sur des lignes separees, indentes avec au moins 2 espaces (le parser les trim, l'indentation est donc indicative)
  • Syntaxe : motcle valeur ou motcle "valeur avec espaces"
  • Les guillemets simples et doubles sont equivalents — le parser les retire automatiquement
  • Les sauts de ligne dans les textes s'ecrivent \n (convertis en vrais sauts de ligne)
  • Les commentaires commencent par // et sont ignores
  • Les lignes vides sont ignorees

Types de valeurs

TypeExempleDescription
Chaine"Hello World"Texte entre guillemets
Nombre42Entier ou decimal
Couleur#FF6347Code hexadecimal CSS
Liste inlineQ1:2026 Q2:2026Espacee, sans guillemets
Astuce : Le parser est tolerant : il trim les espaces en debut/fin de ligne, ignore les commentaires // et les lignes vides. Vous pouvez formater votre DSL comme bon vous semble.

Roadmap #

Les roadmaps representent un parcours temporal avec des jalons (milestones). Il existe 16 variantes visuelles, des plus simples aux plus complexes.

roadmap roadmap 2 roadmap 3 roadmap 4 roadmap 5 ... 16

En-tete

@roadmap                  // variante 1
@roadmap 4               // variante 4
@roadmap 8 "Ma Roadmap" // avec titre

Champs disponibles

ChampSyntaxeDescription
start start "DEBUT" Label du point de depart (optionnel)
finish finish "FIN" Label du point d'arrivee (optionnel)
quarters quarters Q1:2026 Q2:2026 Q3:2026 Q4:2026 Periodes temporelles. Format: label:annee
lanes lanes "Phase One":#23255a "Phase Two":#2d62ed Voies/colonnes (swimlanes). Format: nom:#couleur (couleur optionnelle). Espaces separes.
progress progress 2024 Position de la barre de progression rouge (annee ou index). Defaut: milieu.
milestone milestone Q1:Dev "Titre" "Sous-titre" Jalon. Place quarter:lane optionnel. Sous-titre optionnel.
style style fill #4169E1 Style global ou relatif au milestone courant.
Variantes 1-3 : Utilisent uniquement les milestones simples, start/finish.
Variantes 4+ : Supportent les quarters, lanes, et l'assignation de milestone a un quarter/lane precis via milestone Q1:Dev "Titre".
Variante 15 : Utilise une structure phases interne differente mais le DSL est le meme.

Exemple — Roadmap simple (variante 1)

@roadmap "Feuille de route 2026"
  start "DEBUT"
  finish "FIN"
  milestone "Recherche" "Analyse de marche"
  milestone "Design" "Prototype UX/UI"
  milestone "Developpement" "Sprints d'iteration"
  milestone "Lancement" "Mise sur le marche"

Exemple — Roadmap avec quarters et lanes (variante 4)

@roadmap 4 "Planning 2026"
  start "DEBUT"
  finish "FIN"
  quarters Q1:2026 Q2:2026 Q3:2026 Q4:2026
  lanes Dev Product QA
  milestone Q1:Dev "Alpha" "Prototype interne"
  milestone Q2:Product "Beta" "Preview privee"
  milestone Q3:QA "RC1" "Stabilisation"
  milestone Q4:Dev "GA" "Disponibilite generale"

Exemple — Roadmap 2 avec phases colorees (variante 2)

@roadmap 2 "Timeline Project"
  progress 2024
  lanes "Phase One":#23255a "Phase Two":#2d62ed "Phase Three":#ff4a2b
  milestone "Initiate" "Project kickoff" date:2022 lane:"Phase One"
  milestone "Plan" "Detailed design" date:2023 lane:"Phase One"
  milestone "Develop" "Core features" date:2024 lane:"Phase Two"
  milestone "Test" "QA & validation" date:2025 lane:"Phase Two"
  milestone "Deliver" "Production release" date:2026 lane:"Phase Three"

La barre rouge s'etend du debut jusqu'a l'annee specifiee par progress. Les phases sont affichees en bas comme des bandes colorees en chevron. Les milestones assignees a un lane sont colorees selon la couleur du lane.

Decision Tree #

L'arbre de decision modelise un processus de choix binaire (oui/non) avec des feuilles d'action.

decisionTree decision 2 (Horizontal)

En-tete

@decisionTree
@decision 2 "Arbre de decision"

Champs disponibles

ChampSyntaxeDescription
question question "Question racine?" La question de depart de l'arbre.
yes yes "Source" -> "Cible" Branche positive d'un noeud vers un sous-noeud.
no no "Source" -> "Cible" Branche negative d'un noeud vers un sous-noeud.
leaf leaf "Source" -> "Resultat" Feuille terminale — un resultat final.
Comment ca fonctionne : Les aretes sont definies par des paires source-target. Le parser reconstruit l'arbre en detectant les noeuds racines (ceux qui ne sont jamais cibles) et en construisant recursivement les sous-arbres. Le format est : type "noeudSource" -> "noeudCible".

Exemple — Lancement de projet

@decisionTree "Lancer le projet?"
  question "Demarrer le projet?"
  yes "Budget OK?" -> "Budget Verifie"
  no "Budget OK?" -> "Reporter"
  yes "Budget Verifie" -> "Ressources?"
  no "Budget Verifie" -> "Embaucher d'abord"
  leaf "Ressources?" -> "Lancer"

Drag & Drop #

Les formes et icônes peuvent être déposées directement sur le canvas.

Sources

Panneau sourceÉlémentsAction
ShapesRectangle, Stadium, Ellipse, Diamond, Hexagon, Cylinder, Parallelogram, SubroutineGlisser → déposer sur le canvas
Icons53 icônes SVGGlisser → déposer sur le canvas

Comportement

  • L'élément apparaît à la position exacte du curseur au moment du drop
  • Les coordonnées sont snappées à la grille (10px)
  • Les shapes sont créées en 120×80px par défaut
  • Les icônes sont créées en 80×80px par défaut
  • L'élément déposé est automatiquement sélectionné

Modification après dépôt

  • Clic : sélectionner l'élément
  • Poignées : redimensionner via les 4 coins
  • Drag : déplacer en maintenant le clic
  • PropertiesPanel : changer fill, stroke, stroke width, texte
  • Supprimer : touche Delete/Backspace

Export #

Tous les formats exportent le contenu complet du canvas (shapes + templates + icônes).

Formats disponibles

FormatMéthodeDétails
SVGBouton Export → SVGSVG vectoriel propre, fond blanc, sans artefacts UI
PNGBouton Export → PNGRasterisation 2x (haute résolution), fond blanc
JPGBouton Export → JPGRasterisation avec compression 90%, fond blanc
PPTXBouton Export → PPTXImage rasterisée dans une diapositive PowerPoint
Copier imageBouton Export → Copier imageCopie le canvas en PNG dans le presse-papiers

Copier-coller

La fonction "Copier image" copie le canvas en PNG (2x) dans le presse-papiers système. Vous pouvez ensuite coller directement dans :

  • Figma, Sketch, Adobe XD
  • Microsoft Word, PowerPoint, Outlook
  • Slack, Teams, Discord
  • N'importe quel éditeur d'images

Copier-coller interne

Les formes du diagramme (pas les templates) supportent le copier-coller interne :

  • Ctrl/Cmd + C : copier la sélection
  • Ctrl/Cmd + V : coller (décalé de +30px)
  • Le format JSON { source: "autoDesign", shapes: [...] } est utilisé
